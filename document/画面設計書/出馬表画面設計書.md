## 3. レースヘッダー（race-header-card）

### 3-1. レースナビゲーション（rh-nav）

同日同場の全レースをボタン表示。現在のレースは `active` スタイル（濃紺背景）。  
ボタン群の左端に **競馬場名**（例：「小倉」）を `font-size:1.25rem; font-weight:700` で固定表示する。  
データソース: `GET /api/races?date={ymd}&course={course_code}`

### 3-2. レース基本情報（rh-info）

| 表示要素 | データソース | 備考 |
|---|---|---|
| レース番号 | `race.race_num` | 整数表示 |
| レース名 | `race.race_name_9char` or `race.race_name` | 9文字略称優先 |
| クラスバッジ | `race.grade` + `race.class` | gradeが優先 |
| 発走時刻 | `race.start_time` | HHMM → H:MM |
| 芝/ダバッジ | `race.tds_code` | 1:芝 2:ダ 3:障害 |
| 左右 | `race.migihidari` | 1:右 2:左 |
| 距離 | `race.distance` + "m" | |
| 頭数 | `race.heads` + "頭" | |
| 一番人気信頼度 | calcFavoriteReliability() で計算 | 後述 |

#### クラスバッジ対応表

| race.grade | 表示 |
|---|---|
| `1` | G1（黄バッジ） |
| `2` | G2 |
| `3` | G3 |
| `A` | L |

| race.class | 表示 |
|---|---|
| `A1` | 新馬 |
| `A3` | 未勝利 |
| `05` | 1勝 |
| `10` | 2勝 |
| `16` | 3勝 |
| `OP` | OP |

### 3-3. 一番人気信頼度（fav-rel-meta）

`kijun_ninki = 1` の馬（1番人気）について、JRDB指数群がその評価を支持しているかをS〜Eで表示。  
オッズは**入力に使わない**（市場評価から独立した指標）。  
ホバーでスコア内訳ツールチップを表示。フロントエンド `calcFavoriteReliability()` で計算。

| グレード | スコア | 意味 |
|---|---|---|
| S | ≥ 70 | 全指数が強く支持 |
| A | 55〜69 | 信頼できる本命 |
| B | 25〜54 | 標準（全体1番人気平均） |
| C | 0〜24 | 平均より下 |
| D | −20〜−1 | 支持が薄い |
| E | < −20 | 偽本命の可能性 |

配色：sp-a〜sp-e に準拠（S=金 / A=赤 / B=緑 / C〜D=グレー / E=薄グレー）

**スコアリング内訳**

| ファクター | フィールド | 最高 | 最低 |
|---|---|---|---|
| IDM優位性 | `idm` のレース内順位・差分 | +40 | −20 |
| 情報指数一致 | `joho_index` のレース内順位 | +20 | −15 |
| 展開有利性 | `goal_juni` のレース内順位 | +15 | −10 |
| 調教矢印 | `chokyo_yajirushi` | +15 | −20 |
| 追切指数 | `oi_index` のレース内順位 | +8 | −5 |
| 仕上指数 | `shiage_index` のレース内順位 | +8 | −5 |
| ペース適性 | `ten_index_juni`+`agari_index_juni` | +10 | −6 |

`joho_index = −1`（非開示）の場合は当該ファクターを中立（0点）として除外。

| スコア | セル背景 | テキスト | 単勝回収率実績（穴馬対象） |
|---|---|---|---|
| 100以上 | 薄赤 `#f87171` | 黒・太字 | 374% |
| 50〜99 | ピンク `#fbcfe8` | 黒 | 90〜177% |
| 20〜49 | 黄色 `#fef9c3` | 黒 | 83〜87% |
| 0〜19 | なし（白） | 黒 | 71〜73% |
| 0未満 | グレー `#e5e7eb` | グレー文字 | 40〜65% |

> セル背景色はオッズ10倍以上の馬（穴馬）のみ適用。10倍未満の馬はスコア数値のみ表示。

ホバーでEX指数内訳ツールチップ（13ファクターの寄与値）を表示。

### 4-10. 複勝回収率100%超シグナル（fukusho-signal）

**出典：** [複勝回収率100%超の統合理論レポート.md](../分析レポート/複勝回収率100%超_統合理論レポート.md)（2026-09-06実装、entries.html・watchlist.html共通ロジック）

学習期間(2020/01〜2023/12)・評価期間(2024/01〜2026/08)のwalk-forward検証で複勝回収率100.7%・複勝的中率20.0%（n=3,523）を記録した条件を、出馬表上でリアルタイムに判定して可視化する。

**判定式：** `sc ≥ 3` かつ `kijun_odds` が15倍以上30倍未満

| フラグ | 条件 | 配点 |
|---|---|---|
| idx | `anaba_overall_score≥15` または `honmei_overall_score≥10` | 1 |
| idx_strong | `anaba_overall_score≥50` または `honmei_overall_score≥30` | 1 |
| combo | 騎手×調教師の複勝回収率(`combo_place_rr`)≥100%（`combo_n`≥30） | 1 |
| chokyo | `oi_index≥70` または `shiage_index≥70` | 1 |
| goal | `goal_juni` が1〜2位 | 1 |
| joho | 情報印（`joho_index`のDense Rank）が1〜2位 | 1 |
| ta | `ten_index_juni=1` または `agari_index_juni=1` | 1 |

**表示：**

| 要素 | 内容 |
|---|---|
| 行ハイライト | 該当行を濃いピンク（`#fbcfe8`、ホバー時`#f9a8d4`）で塗り、1列目に赤の左ボーダー（`box-shadow: inset 3px 0 0 #dc2626`） |
| 馬名バッジ | 馬名の右に🎯（赤文字）を表示 |
| ツールチップ | 馬名セルの`data-tip`に「sc=X点×オッズXX.X倍」と検証実績、内訳（該当したフラグ名）を表示 |

> `combo_place_rr`・`combo_n`はライブ運用時点までの実績のみを含むため、この機能自体にlook-aheadバイアスは無い（バックテスト時のみ学習/評価期間分割が必要だった）。

## 6. API仕様

### GET /api/races/:raceKey（レース情報）

T_BAC からレース基本情報を返す。

### GET /api/races?date={ymd}&course={course_code}（同日同場レース一覧）

レースナビゲーションボタン生成に使用。

### POST /api/races/:raceKey/marks（自分の予想印を保存）

**リクエストボディ：** `{ uma_num: string, mark: string | null }`

`T_MY_MARK`に upsert する。`saveMyMark()`がプルダウン変更時に呼び出す（4-9参照）。

## 7. 推奨買い目セクション（betting-wrap）

| 項目 | 内容 |
|---|---|
| 実装場所 | `public/entries.html` → `renderBetting(rows)` 関数 |
| 表示位置 | 出馬表テーブルの直下 |
| 表示条件 | **全レース・常時表示**（日付・条件による制限なし） |
| 最終更新 | 2026-09-06（買い目フォーメーション記述を実装に合わせて修正） |

### 7-1. 概要

出馬表の全フィールドを使って各馬を5軸で独立評価し、「複数のシグナルが同一馬に重なっている」馬を機械的に検出して買い目を提示するセクション。  
**単一指数の高い馬を並べるだけでなく、人間が見落としやすいクロスファクターの一致を可視化することが目的。**

---

### 7-2. 評価アーキテクチャ（evalHorse）

各馬に対して以下の5軸でシグナルを発火し、重みの合計（スコア）を算出する。

#### 能力フロアチェック（全B/C/E/調教シグナルのゲート）

**B・C・展開・調教のシグナルは、能力フロアを通過した馬にのみ発火する。**  
これにより「コンボ回収率が高いだけの低能力馬」「調教矢印が上向きなだけの調教SP=D馬」を誤って注目馬に選定しない。

能力フロア（`abilityOk`）は以下のいずれかを満たせば true：

| 条件 | フィールド |
|---|---|
| 本命指数 ≥ 10 | `honmei_course_score` |
| EX指数 ≥ 15 | `anaba_course_score` |
| 展開予測が上位45%以内 | `goal_juni` / validGoalCnt |
| IDM が同レース中央値以上 | `idm` / idmMedian |

情報指数（D）だけはゲートなし（JRDB取材情報は能力と独立した情報源のため）。ただし `abilityOk = false` の場合は重みを半減して発火する。

#### A. 指数シグナル

| 条件 | ラベル例 | 重み |
|---|---|---|
| isHonmei かつ `honmei_course_score` ≥ 50 | 本命指数XX（回収134%帯） | 3 |
| isHonmei かつ ≥ 30 | 本命指数XX（回収100%超） | 2 |
| isHonmei かつ ≥ 10 | 本命指数XX | 1 |
| isAnaba かつ `anaba_course_score` ≥ 100 | EX指数XX（最上位） | 3 |
| isAnaba かつ ≥ 50 | EX指数XX | 2 |
| isAnaba かつ ≥ 15 | EX指数XX | 1 |

- `isHonmei` : `kijun_odds` > 0 かつ < 10
- `isAnaba`  : `kijun_odds` ≥ 10
- 上記条件は `else if` チェーンのため、各馬に発火するのは最大1件

#### B. 騎手×厩舎コンボ回収率

`T_COMBO_RECOVERY` の `place_recovery`（複勝回収率）と `total_count`（サンプル数）で判定。  
**補助シグナルとして位置づけ、最大1ptに抑える。** 偶発的な高回収率を過大評価しないための設計。

| 条件 | 重み |
|---|---|
| `combo_place_rr` ≥ 130% かつ `combo_n` ≥ 10 | 1 |
| `combo_place_rr` ≥ 110% かつ `combo_n` ≥ 7 | 1 |

#### C. 厩舎穴セグメント実績

`T_KYUSHA_FACTOR_AGG` の `anaba_place_rr`（穴馬帯の複勝回収率）を使用。  
**isAnaba（オッズ≥10倍）の馬にのみ適用。本命帯の馬には発火しない。**

| 条件 | 重み |
|---|---|
| `kyusha_anaba_place_rr` ≥ 130% かつ `kyusha_anaba_n` ≥ 10 | 3 |
| `kyusha_anaba_place_rr` ≥ 110% かつ `kyusha_anaba_n` ≥ 7 | 2 |

#### D. 情報指数とオッズ乖離

`joho_index = -1`（非開示）の馬はこの軸をスキップする。

| 条件 | 重み |
|---|---|
| `joho_index` ≥ 7 | 3 |
| `joho_index` ≥ 5 | 2 |
| `joho_index` ≥ 3 | 1 |
| 上記に加え `odds` ≥ 5倍の場合（市場過小評価ボーナス） | +2 |

市場過小評価ボーナスは「取材では高評価なのに市場オッズが高い」という情報非対称を検出するもの。

#### E. ペースシナリオ

出走馬全体の脚質（`kyakushitsu`）分布からペースを予測し、有利な脚質の馬を加点。

**ペース判定ロジック**

| 判定 | 条件 | 恩恵を受ける脚質 |
|---|---|---|
| ハイペース | 逃+先行頭数 ≥ 全頭数の38% | 差し（3）・追込（4） |
| スローペース | 逃げ≤1頭 かつ 先行≤1頭 | 逃げ（1）・先行（2） |

| 加点条件（ハイペース時） | 重み |
|---|---|
| 差し・追込 かつ `agari_index_juni` ≤ 2 | 3 |
| 差し・追込（上がり順位問わず） | 2 |

| 加点条件（スローペース時） | 重み |
|---|---|
| 逃げ・先行 かつ `ten_index_juni` ≤ 2 | 3 |
| 逃げ・先行（前3F順位問わず） | 2 |

#### 調教シグナル（補助・能力フロア必須・相対評価）

**能力フロアを通過した馬のみ**発火。追切指数は絶対値でなく**レース内ランク上位25%**で判定する。  
矢印ダウン（↓/↓↓）は能力フロアに関わらずスコアを−2する（表示タグなし）。

| 条件 | 重み |
|---|---|
| `chokyo_yajirushi` = '1'（↑↑） かつ abilityOk | 2 |
| `chokyo_yajirushi` = '2'（↑） かつ abilityOk | 1 |
| `oi_index` レース内上位25% かつ abilityOk | 1 |
| `goal_juni` ≤ 2 かつ abilityOk | 2 |
| `chokyo_yajirushi` = '4'（↓） | −2（減点のみ） |
| `chokyo_yajirushi` = '5'（↓↓） | −2（減点のみ） |

> `chokyo_yajirushi` のコード体系: 1=↑↑、2=↑、3=→、4=↓、5=↓↓

---

### 7-3. 注目馬の選定基準

以下を**すべて満たす**馬を「注目馬」として抽出。スコア降順で最大7頭まで表示。

| 条件 | 理由 |
|---|---|
| `abilityOk = true` | 能力最低クラスの馬を除外 |
| 正のシグナルが2カテゴリ以上（`w > 0` なもの） | 単一ファクター依存の排除 |
| 合計スコア `sc >= 3` | 閾値以下は買い目に値しない |

---

### 7-4. 表示レイアウト

#### ヘッダー行

- タイトル：「推奨買い目（複合シグナル分析）」
- ペース予測テキストをヘッダー右に常時表示（例: 「前6頭(逃2先4) → ハイペース想定」）

#### 注目馬カード

各注目馬を1枚のカードで表示。

```
┌────────────────────────────────────────────────────┐
│ ⑫  アルジャンナ  2.3倍 / 先 / 調教↑               │
│  ●●●●○○                                            │
│  [本命指数62（回収134%帯）] [騎×厩 複勝131%(23戦)] │
└────────────────────────────────────────────────────┘
```

- 左ボーダー色：本命馬＝ピンク（`#f9a8d4`）、穴馬＝緑（`#6ee7b7`）
- スコアドット：`●` を合計スコア（`sc`）の数だけ上限6で表示、残りは `○`。右隣に `Xpt` を表示（常時 `#6b7280`）
- シグナルタグ：カテゴリ別の色（A=黄、B=青、C=緑、D=ピンク、乖離=橙、展開=紫、調教=緑、goal=水）
- タグの個数はシグナル件数と一致するが、スコアはシグナル重みの合計なので `●` 数とタグ数は一致しない（重み2〜3のシグナルは `●` 複数個分に相当）

> **注：** 現在の `renderBetting()` は券種別のフォーメーション（馬連・ワイド・三連複の買い目点数）は生成しない。表示するのは上記の**注目馬カード一覧のみ**（最大7頭）。`evaluateRaceSignals()`が計算する`honmeiAnchors`（本命指数≥30の軸候補）・`anabaAnchors`（EX指数≥50の軸候補）は、このセクションではなく`recommendRanking()`経由で4-9の「推奨印」フォールバック順位付けにのみ使われる。

---

### 7-5. 「なし」の場合

`notable`（注目馬）が0頭の場合：「注目馬なし（複合シグナルが揃った馬が不在）」を表示して終了。

---

### 7-6. 実装メモ

- `<table>` タグを使うと `entries.html` のグローバルCSS（`table-layout:fixed`）が当たってレイアウトが崩れる → **`<div>` + flexbox のみで組む**
- `renderBetting(rows)` は `load()` 内で `renderTable()` と並んで毎回呼ばれる（日付・条件による制限なし）
- `evaluateRaceSignals(rows)` は `renderBetting()`（注目馬カード表示）と `computeRecommendMarks()`（4-9の推奨印算出）の両方から呼ばれる共通ロジック（同じ計算を2回書かないための共通化）
