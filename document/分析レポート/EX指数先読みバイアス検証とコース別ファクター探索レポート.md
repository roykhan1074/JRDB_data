## 1. 発端：EX指数の水増しが実損失を引き起こした

`factor-recovery.html`の「EX指数帯別成績」パネルは、`course_score`が「100以上」の帯で単勝回収率194.8%と表示していた。この数字を根拠に`src/server.ts`の`/api/watchlist`が`matchEx = ex_course >= 100`という条件で馬を推奨していた。

しかしこの数字は「全期間データを過去のレースにも遡って適用した集計」であり、先読みバイアスを含んでいた。

### 1-1. 先読みバイアスの2つの原因

**原因A（時系列の先読み）：** `T_ANABA_FACTOR_AGG`はコース別回収率を全期間（過去〜未来を区別せず）集計しており、過去のレースをこの値で採点すると、そのレース時点では存在しなかった未来のデータが混入する。

**原因B（小サンプル過学習、こちらが本命）：** `course_score`はコース×芝ダ×距離帯という細かい粒度でファクター別回収率を集計するため、1グループのサンプル数が数件〜数十件しかないことがある。`sql/anaba_index.sql`のPart3コース別集計ブロックの一部（ten_rank/agari_rank/ichi_rank/goal_rank/tenkai_comboのコース別）には`HAVING COUNT(*) >= N`のような最低サンプル数ガードが一切なかった。n=3で偶然1頭の万馬券的中があれば、そのバケットのwin_recoveryは即座に数百%に跳ね上がり、course_scoreに無条件加算される。

### 1-2. ホールドアウト検証の実測結果

2020〜2023年のみでファクター統計を作り、2024〜2026年のレースを採点する検証を行った（`course_score`ベース、kijun_odds≧10の穴馬母集団）。

| course_score帯 | 素の回収率（先読みあり、全期間集計） | 実測回収率（先読みなし、ホールドアウト） |
|---|---|---|
| 50〜100 | 単111.4% | 単65.2% / 複71.6% |
| 100以上 | 単189.4%（画面表示と近似） | 単76.4% / 複76.3% |

→ **「100以上帯：単勝194.8%」は実質ほぼ架空の数字**。対応として`src/server.ts`の`matchEx = ex >= 100`トリガーは既に無効化済み。

詳細な手法（縮小推定・14ファクター個別診断等）は`CLAUDE.md`の「指数/スコアETL実装時の必須チェック」セクション4・5に記録済みのため本レポートでは割愛する。

## 2. EX指数改良の試み：11アプローチすべて失敗

「EX指数を改良して高スコア帯の単勝回収率が100%を超える指数を作る」ことを試みたが、**11個の独立した統計的手法すべてで失敗**し、80〜93%の壁に収束した。詳細な手法一覧は`CLAUDE.md`の「### 5. 【2026-09-23、EX指数ブラッシュアップ試行】」セクションに記録済み。要約：

- 先読み排除のみ・縮小推定（win/place基準）・分位点分析・14ファクター個別診断・複合スコア構築・combo/kyusha再検証・オッズ帯分割 → **すべて80〜93%止まり**
- 唯一「100%超え」に見えた結果（オッズ30倍以上×高スコア、単勝103.8%）も、**4期間チェック（学習期間/2024/2025/2026）で即座に崩壊**（9.7%→233.7%→26.8%と乱高下）。2025年の万馬券1〜2件が合算を歪めただけの見せかけだった。

**教訓：** JRDB指数の単純加算という設計思想そのものが、標準的な統計補正をすべて施しても単勝回収率100%を超えるだけの情報量を持たない可能性が高い。ここで**方針転換**し、競馬のドメイン知識に基づく仮説駆動アプローチに切り替えた。

## 3. 検証手法：4期間チェック（本レポート共通の方法論）

以降のすべての検証で、以下の方法論を統一して使用した。

1. **学習期間（<20240101）と検証期間を「2024年」「2025年」「2026年（9月まで）」の3つに独立して分割**（sc walk-forward検証レポートの第5章と同じ発想）。
2. 単一のtrain/testホールドアウト1回だけで「良さそう」と判断しない。**4期間すべてで基準を満たすか、満たさない場合はどの期間が弱いかを必ず確認する**。
3. 判定基準（ユーザーとの合意）：「4期間すべて100%超」は厳しすぎるため、**ニアリーイコールも許容**する：
   - 4期間中3期間が100%超で、残り1期間も90%に近い
   - 2期間しか100%を満たさなくても、残り2期間が90%超で安定している

### 4期間評価の再現用SQLテンプレート

```sql
SET @cutoff = '20240101';
SELECT
  CASE WHEN ymd<@cutoff THEN '学習期間' WHEN ymd<'20250101' THEN '2024'
       WHEN ymd<'20260101' THEN '2025' ELSE '2026' END AS period,
  COUNT(*) n,
  ROUND(SUM(win_pay)/COUNT(*),1) win_recovery,
  ROUND(SUM(place_pay)/COUNT(*),1) place_recovery
FROM <対象母集団テーブル>
WHERE <フラグ条件>
GROUP BY period ORDER BY period;
```

## 4. 仮説駆動アプローチ（穴馬母集団・kijun_odds≧10限定）

以下は当初「EX指数の代替」として、オッズ≧10倍（穴馬）母集団に限定して検証したもの。

| 仮説 | 内容 | 結果 |
|---|---|---|
| H1 | 脚質×直線長（3段階: 短/中/長） | **否定**。脚質2(先行)がどの直線長でも一貫して好成績なだけで新しい相互作用なし |
| **H2** | **距離帯×テン/上がり指数**（短距離=テン1位 / それ以外=上がり1位が「距離適性マッチ」） | **有望**。複勝: 94.5%(学習)→95.6%(2024)→68.6%(2025)→78.4%(2026)。3/4期間で非マッチ群を20〜29pt上回る大差 |
| H3 | クラス×IDM | **否定**。高クラス帯でIDM<30の馬がn=124〜143と少なすぎ無意味 |
| H4 | 小回りコース×内枠(1-2) | 単勝は0/4だが3/4期間が81〜96%に接近。複勝は全期間72〜79%で低分散・安定 |
| H5 | 少頭数(9頭以下)×先行(脚質2) | 複勝3/4期間が92〜104%（2024年のみ59.4%と崩壊） |
| **H6** | **芝限定・距離適性マッチ**（H2を芝のみに限定） | **最有力（当時）**。単勝: 81.8%→89.6%→**107.9%→111.3%**。時系列で単調増加、非マッチ群には全期間12〜40pt差 |
| H15 | 騎手勝率(JRDB提供値kishu_tansho_rate)5〜10%帯 | 大サンプル(n=1〜1.7万)で再現性あり(学習78.5%/検証76.2%)だが100%未達 |
| H16 | 展開記号(tenkai_kigo)=3 | 中程度の再現性(78.3%/71.8%) |

**H6を主軸にH4/H5/H15を単純OR条件で複合化した結果、H6単体より悪化した**（80.0/87.1/107.0/103.4% vs H6単体の81.8/89.6/107.9/111.3%）。単純にフラグを足し合わせるとノイズの多い要素（特にH5）が信号を薄める。→ **これが「今後の宿題」冒頭で述べる複合化の難しさの実例**。

## 5. コース単位分析への回帰（ユーザー指摘により方針転換）

「東京芝1600mのように競馬場・芝ダ・距離の組み合わせを『コース』と定義するのが競馬の大基本」という指摘を受け、個別コース単位での検証に転換した。

### 5-1. 最初の失敗：穴馬母集団のままコースを絞ると崩壊する

個別コース×穴馬(オッズ≧10)×特定脚質のように条件を重ねると、年間サンプルが50〜175件まで縮小し、1回の万馬券的中や0勝が回収率を±50pt単位で揺さぶる。例：

- 中山ダ1200m×テン1位（穴馬限定）：2025年は**59戦0勝**、複勝41.9%
- 阪神ダ1800m×先行（穴馬限定）：2024年n=50で複勝106.4%、2025年n=175で60.0%

→ **これは実装ミスではなく、「個別コース×穴馬限定」という掛け合わせが、このデータ量では統計的に成立しないという構造的制約**。

### 5-2. 解決策：オッズ制限を撤廃

EX指数はもともと「穴馬指数」として定義されていたが、コース特性そのものは穴馬限定の話ではない。**オッズ制限を外して全馬を対象にすると、同じコース単位でもサンプルが2〜9倍に増える**（ファクターの出現頻度による。ten_juni=1のようにレースに1頭しかいないファクターは増加率が小さく、kyakushitsu=2のように複数頭該当するファクターは増加率が大きい）。

## 6. 全コース自動スキャン：手法と発見

### 6-1. 手法

82コース（学習期間n≧100の条件でフィルタ）× 6つの標準ファクター仮説（テン1位・上がり1位・逃げ先行・差し追込・内枠1-3・外枠6-8）を全組み合わせで自動計算し、4期間チェックで足切りした。**オッズ制限なし・class≠A1（新馬除く）・芝ダ両方**が対象母集団。

### 6-2. 再現用SQL（ベーステーブル構築）

```sql
DROP TABLE IF EXISTS T_AC_BASE;
CREATE TABLE T_AC_BASE (
  course_code CHAR(2), tds_code CHAR(1), distance SMALLINT,
  ymd CHAR(8), period VARCHAR(6),
  ten_juni TINYINT, agari_juni TINYINT, kyakushitsu CHAR(1), waku_num TINYINT,
  win_pay INT, place_pay INT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO T_AC_BASE
SELECT
  k.course_code, TRIM(b.tds_code), CAST(TRIM(b.distance) AS UNSIGNED),
  b.ymd,
  CASE WHEN b.ymd<'20240101' THEN 'train' WHEN b.ymd<'20250101' THEN 'y2024'
       WHEN b.ymd<'20260101' THEN 'y2025' ELSE 'y2026' END,
  CASE WHEN TRIM(k.ten_index_juni) BETWEEN '01' AND '99' THEN CAST(TRIM(k.ten_index_juni) AS UNSIGNED) ELSE NULL END,
  CASE WHEN TRIM(k.agari_index_juni) BETWEEN '01' AND '99' THEN CAST(TRIM(k.agari_index_juni) AS UNSIGNED) ELSE NULL END,
  NULLIF(TRIM(k.kyakushitsu),''),
  CASE WHEN TRIM(k.waku_num)<>'' THEN CAST(TRIM(k.waku_num) AS UNSIGNED) ELSE NULL END,
  CASE WHEN s.ijou_kubun IN ('0','') THEN COALESCE(CAST(TRIM(s.win) AS UNSIGNED),0) ELSE 0 END,
  CASE WHEN s.ijou_kubun IN ('0','') THEN COALESCE(CAST(TRIM(s.place) AS UNSIGNED),0) ELSE 0 END
FROM T_KYI k
INNER JOIN T_BAC b ON b.course_code=k.course_code AND b.year_code=k.year_code
  AND b.kai=k.kai AND b.day_code=k.day_code AND b.race_num=k.race_num
INNER JOIN T_SED s ON s.course_code=k.course_code AND s.year_code=k.year_code
  AND s.kai=k.kai AND s.day_code=k.day_code AND s.race_num=k.race_num AND s.umaban=k.uma_num
WHERE TRIM(b.tds_code) IN ('1','2') AND TRIM(b.`class`) <> 'A1' AND s.order_of_finish IS NOT NULL;
```

その後、ファクターごとに`GROUP BY course_code, tds_code, distance, period`で集計し、`course_code,tds_code,distance,factor`単位でピボットして4期間の`n / win_recovery / place_recovery`を横並びにし、以下の条件で足切りした：

```
n_train>=100 AND n_2024>=30 AND n_2025>=30 AND n_2026>=30
AND ( 4期間中2〜3期間で回収率>=95〜100%、かつ残りの期間もLEAST(...)>=75〜85% )
```

| コース×ファクター | 直近3年合計n | 学習期間 | 2024 | 2025 | 2026 | 特記事項 |
|---|---|---|---|---|---|---|
| **函館芝1200m×逃げ先行**（複勝） | 603 | 79.3% | **106.4%** | **106.0%** | **102.4%** | 直近3年連続で100%超え。学習期間のみやや低い |
| **中山芝1600m×上がり1位**（複勝） | 148 | 97.0% | 96.9% | 96.5% | **102.8%** | 4期間全て90%超、変動幅わずか6.3ポイントという異例の安定性 |

### 6-4. 既存レポートとの矛盾点（要調査・未解決）

`コース別ファクター有効性分析レポート.md`（2026-04-29）は**テン1位勝率 vs 上がり1位勝率**（的中率ベース、全期間集計、先読み・walk-forward検証なし）で函館芝2000を「末脚▶★★★（+10.4、上がり指数＝末脚が有利）」と分類しており、本レポートの「逃げ先行が単勝で有利」という発見と**方向が逆**に見える。

考えられる理由（未検証）：
1. 指標が異なる（的中率 vs 回収率）。逃げ先行馬は「勝率は低いが市場に過小評価されて回収率は良い」というパターンなら両立しうる。
2. 既存レポートは先読み・年別ブレを考慮しない全期間集計のため、本レポートのような年別頑健性チェックをしていない。
3. 逆に本レポートの函館の結果自体が、n=137〜227と決して大きくないサンプルによる偶然の可能性も否定できない。

**次のセッションでの優先タスクの1つとして、この矛盾を解消すること。**

## 7. 全フィールド自動マイニング（人力の仮説立てではなく機械的網羅探索）

ユーザーから「これまでの分析は人間の劣化コピーになっている、AIの強みを見せてほしい」との指摘を受け、**個別に仮説を立てて検証する方式から、T_KYIの30フィールドを一括・機械的にスキャンする方式に転換**した。

### 7-1. 手法

Pythonが使えない環境のため、SQLのみで実装。

1. T_KYIの候補フィールド30個（idm/テン/上がり/位置/ペース/LS/激走の各順位、脚質、上昇度、距離適性×2、重適性、芝適性、ダ適性、調教矢印、厩舎評価、万券印、ブリンカー、蹄コード、見習い区分、輸送区分、馬記号、ローテーション、性別、出遅れ指数、出遅れ率、入厩何走目、騎手勝率、騎手複勝率、枠番、頭数）を1つの長形式テーブル（field_name, category, period, win_pay, place_pay）にUNION ALLで展開（**746万行**）。
2. `GROUP BY field_name, category, period`で集計。
3. **学習期間（train）のみを見て各フィールドのbest/worstカテゴリを機械的に特定**（n≧500）。
4. そのbest/worstカテゴリが**検証期間（2024〜2026合算、n≧200）でも同じ方向を維持しているか**を確認し、`test_gap`（検証期間でのbest−worstの複勝回収率差）で全31フィールドをランキング。

この手順は「学習期間で仮説を立て、検証期間で裏切られていないか確認する」という、これまでのレポート全体を貫く方法論を、**手動で1つずつではなく全フィールドに対して機械的に一括適用**したもの。

### 7-2. 再現用SQL（要点）

```sql
-- 長形式へのUNION ALL展開（フィールド数分繰り返す。例）
INSERT INTO T_MINE_LONG
SELECT 'chokyo_yajirushi', chokyo_yajirushi, period, win_pay, place_pay
FROM T_MINE_BASE WHERE chokyo_yajirushi IS NOT NULL
UNION ALL SELECT 'kyusha_hyoka', kyusha_hyoka, period, win_pay, place_pay
FROM T_MINE_BASE WHERE kyusha_hyoka IS NOT NULL
-- ... 他29フィールド分繰り返す

-- 集計
CREATE TABLE T_MINE_AGG AS
SELECT field_name, category, period, COUNT(*) n,
  ROUND(SUM(win_pay)/COUNT(*),1) win_r, ROUND(SUM(place_pay)/COUNT(*),1) place_r
FROM T_MINE_LONG GROUP BY field_name, category, period;

-- 学習期間のbest/worstカテゴリ特定 → 検証期間で答え合わせ（本文参照）
```

waku_numが単体では逆転（負のgap）したことは、5〜6章の「枠順効果はコース特性との相互作用でしか現れない」という発見と整合する。

### 7-4. 最大の新発見：調教矢印・厩舎評価が4期間すべてで完璧に単調

これまで一度も検証していなかった2フィールドが、**全4期間で完全に順序が保たれる**という、本セッション随一の再現性を示した。

**chokyo_yajirushi（調教矢印）複勝回収率：**

| 区分 | 学習期間 | 2024 | 2025 | 2026 |
|---|---|---|---|---|
| 1（最高評価） | 85.5% | 82.5% | 82.8% | 82.3% |
| 2 | 79.6% | 82.4% | 80.6% | 82.1% |
| 3 | 72.2% | 70.2% | 69.8% | 69.2% |
| 4（最低評価） | **45.9%** | **24.6%** | **26.3%** | **45.2%** |

**kyusha_hyoka（厩舎評価）複勝回収率：**

| 区分 | 学習期間 | 2024 | 2025 | 2026 |
|---|---|---|---|---|
| 1（最高評価） | 83.7% | 81.8% | 83.6% | 74.6% |
| 2 | 80.6% | 79.0% | 77.6% | 75.1% |
| 3 | 73.7% | 72.5% | 71.7% | 72.7% |
| 4（最低評価） | **48.0%** | **40.2%** | **41.9%** | **26.4%** |

いずれも4区分の順序が4期間すべてで一度も入れ替わらない。特に「4（最低評価）」は毎年25〜48%という壊滅的な回収率で、**「避けるべき馬を機械的に検出できる」という強力な除外フィルタ**として使える。

**組み合わせテスト**（chokyo_yajirushi∈{1,2} AND kyusha_hyoka∈{1,2}）：複勝 81.6%(学習)→81.0%(2024)→79.8%(2025)→77.8%(2026)。100%は超えないが**変動幅3.8ポイントという極めて低い分散**で、これまでのどの発見よりも年ブレが小さい。

### 7-5. この手法から得られた教訓

- **人力で1つずつ仮説を立てる方式（4〜6章）では、この2フィールドに辿り着けなかった**。理由は単純で、`chokyo_yajirushi`と`kyusha_hyoka`は「調教矢印」「厩舎評価」という地味な名前で、EX指数や脚質・展開のような目立つ指数の陰に隠れており、優先的に検証する対象として思いつきにくかった。
- 一方で機械的スキャンは「学習期間でどのフィールドが良さそうか」を判断する目が無いため、**seibetsu_code（性別）やhizume_code（蹄コード）のような、実務的な意味が薄い／解釈が難しいフィールドも同列にランキングされてしまう**。人間による事後的な解釈・取捨選択は依然として必要。
- **今後の指数改良は、この7章の機械的スキャンを起点にし、6章のコース別分析や4章の仮説駆動アプローチと組み合わせるのが最も効率的**。具体的には次章の宿題を参照。

## 8. 今後の宿題

ユーザーからの明示的な宿題：

### 8-1. 複数ファクターの掛け合わせ

単一ファクターでは限界がある（本レポート全体を通じて、単一ファクターの複勝回収率は概ね70〜110%のレンジに収まり、100%を大きく超える例は少ない）。次にやるべきは：

- 6-3で発見した有望コース×ファクターの組み合わせに、**同じコース内で別のファクター（枠順・頭数・騎手勝率・調教矢印・厩舎評価等）をAND条件で追加**し、サンプルを絞り込みながらも回収率をさらに押し上げられるか検証する。**特に7章で発見したchokyo_yajirushi・kyusha_hyokaは、既存のコース別発見（6-3）と相関が低いと考えられ（コース特性と調教評価は独立した情報のはず）、掛け合わせの優先候補**。
- ただし2章・4章で学んだ通り、**単純にフラグをOR/ANDで足し合わせるだけでは悪化することがある**（H6+H4+H5+H15の複合化がH6単体を下回った実例）。掛け合わせる前に、各ファクターが「本当に独立した情報を持っているか」（相関していないか）を確認すべき。

### 8-2. 足を引っ張るファクターの検出・除外

CLAUDE.mdに記録した「14ファクター個別診断」（学習期間の予測と検証期間の実績を比較し、順位が逆転するファクターを除外する手法）を、**コース単位の複合指数構築でも同様に適用する**。7章の全フィールド自動マイニング手法（`T_MINE_LONG`/`T_MINE_AGG`パターン）はこれをそのままコース単位に応用できる（`GROUP BY`に`course_code,tds_code,distance`を追加するだけ）。具体的な進め方の提案：

1. 6-3の有望コースを起点に、そのコースで使える全ファクター（7章でスキャンした30フィールドすべて）を洗い出す。
2. 各ファクターを単体で学習期間vs検証期間の順位一致度を診断する（7-1節のSQLテンプレートをコース単位に拡張）。
3. 順位が再現するファクターのみを、縮小推定（shrinkage）を使いながら加算する。
4. 4期間チェックで頑健性を最終確認する。

### 8-3. その他の未解決事項

## 9. 再現に必要な情報まとめ

- DB接続：`.env`の`DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME`（mysql CLI経由、`--batch --default-character-set=utf8mb4`）
