**対象：** `public/entries.html` の `evaluateRaceSignals()`（出馬表の予想印・推奨買い目・注目馬ハイライトの共通ロジック）が算出する複合シグナルを全期間データに対して再現し、実際の単勝・複勝回収率を検証

## ロジック概要

`evaluateRaceSignals()` は各馬を以下8カテゴリで評価し、該当すれば重み付きスコアを加算する。

| カテゴリ | 内容 | ゲート条件 |
|---|---|---|
| idx | 本命指数(≥10/30/50)・EX指数(≥15/50/100) | なし（常時評価） |
| combo | 騎手×厩舎複勝回収率（T_COMBO_RECOVERY） | 能力フロア必須 |
| kyusha | 厩舎穴セグメント複勝回収率（穴馬のみ） | 能力フロア必須・isAnaba必須 |
| joho | 情報指数の高さ | なし（能力フロア未通過は重み半減） |
| gap | 情報指数高×オッズ5倍以上（市場過小評価） | なし（能力フロア未通過は重み半減） |
| pace | 展開シナリオ（ハイペース×差し・追込／スローペース×逃げ・先行）適性 | 能力フロア必須 |
| chokyo | 調教矢印↑↑/↑、追切指数レース内上位25%（矢印↓↓/↓はスコア減算のみでゲートなし） | 能力フロア必須 |
| goal | 展開予測順位1〜2位 | 能力フロア必須 |

**能力フロア**：本命指数≥10 or EX指数≥15（idx系シグナル）、または展開予測順位が上位45%以内 or IDMがレース内中央値以上（能力プロキシ）のいずれかを満たすこと。B/C/E/pace/chokyo/goal系シグナルはこれを通過した馬にのみ発火する。

**注目馬判定**：能力フロア通過 かつ 該当カテゴリ数2つ以上 かつ 合計スコア(sc)≥3。

## まとめ：実践的な活用フレームワーク

### 段階別アプローチ

```
Step 1: ネガティブフィルター
  └── 調教矢印↓↓（sc=-2該当） → 単回収27.0%・的中0.4%、除外必須

Step 2: スコア閾値の見直し
  └── 現行「sc≥3」→「sc≥4」に引き上げ推奨
      対象: 35,848件→23,631件（約66%）に絞り込み
      効果: 単回収 88.3%→111.4%

Step 3: 核となる2ファクターへの重点評価
  ├── idx（本命指数/EX指数）とcombo（騎×厩複勝回収率）が唯一プラス単体
  ├── 両方同時発火（combo+idx）で単回収273.3%（n=5,711、★★★）
  └── idx+kyushaの組み合わせだけは避ける（57.1%、二重カウントの疑い）
```

### 重要な注意事項

1. **look-aheadバイアス**：combo（T_COMBO_RECOVERY）・kyusha（T_KYUSHA_FACTOR_AGG）は全期間データで事前集計された値をそのまま使用しており、時系列的な先読みバイアスを含む。実運用の回収率はこれより低くなる可能性が高い（他の分析レポート群と同様の限界）。
2. **サンプル数の罠**：sc≥10や一部の複合パターン（n<200）は参考程度。continuous observationが必要。
3. **idx+kyushaの重複問題**：kyushaはisAnaba限定発火のためidxのEX指数評価と情報が重複しやすく、単純な加算スコアリングでは過大評価・過小評価どちらも起こりうる。将来的にはスコア設計の見直し（重複ファクターの重み調整）を検討する余地がある。
4. **本分析はentries.htmlの現行ロジックをそのまま検証したものであり、ロジック自体の妥当性の限界（能力フロアの定義、重みの割り当てなど）は別途検証が必要。**

### 今後の課題

- combo・kyushaの先読みバイアスを除去した時系列分割（walk-forward）検証
- idx+kyushaの重複を解消したスコアリング方式の再設計
- sc≥4への閾値変更を実装した場合のUI・推奨買い目ロジックへの影響確認
