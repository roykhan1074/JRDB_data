# ブリンカー指数 仕様書

> 最終更新: 2026-09-02

---

## 1. 概要

**ブリンカー指数**は、`document/分析レポート/ブリンカー回収率傾向分析レポート.md` の分析結果をもとに、初装着・再装着ブリンカー馬について「回収率期待がどれだけ高いか」を数値化した指数。

**指数が高いほど回収率が上がるように設計されている**が、後述のバックテスト結果により、**連続値としての解像度は低く、実用上は A/B/C の3段階グレードのみを信頼して使うべき**という重要な制約がある。この点を隠さず明記することが本仕様書の主目的の一つでもある。

---

## 2. 対象馬の定義

| 項目 | 定義 |
|------|------|
| 対象 | `T_KYI.blinker IN ('1':初装着, '2':再装着)` の馬のみ |
| 非対象 | 継続(`3`)・非装着(NULL)の馬は指数を持たない（スコアなし） |
| ETL対象範囲 | `T_BAC.tds_code IN ('1','2')`、`class <> 'A1'`（course_recovery_index等と同条件） |

初装着・再装着は母集団の性質・妙味の出る条件が正反対であることが分析レポートで確認されているため、**指数はブリンカー種別ごとに別々の基準（別々のベースライン・別々のファクター回収率テーブル）で計算する**。

---

## 3. 指数の仕組み

### 3.1 基本思想

EX指数・コース回収率指数と同じ「回収率偏差の合算」方式を踏襲する。

```
score = Σ（各ファクターの"そのブリンカー種別内"での単勝回収率 − そのブリンカー種別の平均単勝回収率）
```

- ベースライン：初装着母集団の平均単勝回収率（約80.0%）／再装着母集団の平均単勝回収率（約87.3%）
- 各セルの件数が30件未満の場合は、初装着+再装着を合算した「プール」母集団の値にフォールバックする

### 3.2 使用ファクター（9種、基準オッズは含まない）

| ファクター | 内容 |
|---|---|
| コース適性 | 芝ダ × 距離帯（短/マイル/中距離/長距離） |
| クラス | 未勝利・1勝・2勝・3勝・オープン |
| 脚質 | 逃げ・先行・差し・追込 |
| 性別 | 牡・牝・セン |
| ローテーション | 0〜2週・3〜8週・9週以上 |
| 枠番 | 1〜8（生値） |
| IDM順位 | レース内でのIDM順位（1位/2〜3位/4〜6位/7位以下） |
| テン指数順位 | 同上のテン指数版 |
| 上がり指数順位 | 同上の上がり指数版 |

**基準オッズは指数に含めない。** 指数と実際のオッズを独立にクロスチェックできるようにするため（コース回収率指数と同方針。詳細はそちらの仕様書§5-1参照）。ブリンカー回収率傾向分析レポート第2章で確認された「初装着は基準オッズ15〜30倍、再装着は30倍以上で妙味最大」という知見は、**指数とは別に、馬券判断時にオッズ帯を目視で確認する運用**を前提とする。

## 4. バックテスト結果と重要な制約

### 4.1 検証方法

学習期間(2020-2023)のみでファクター回収率を集計し、学習期間・評価期間(2024-2026)の両方にスコアを付与してスコア帯別に回収率を比較した（コース回収率指数と同じ手法）。加えて、時系列分割で不安定さが見られたため、**時系列と無関係なランダム50/50分割**でも同様の検証を行った。

### 4.2 結果：連続値としては中間帯が不安定

| 検証方法 | 結果 |
|---|---|
| 時系列分割（9ファクター） | 上位帯(30+)は学習・評価とも高い回収率を維持。ただし中間帯(0〜29・-1〜-15)は学習・評価で順位が入れ替わる、あるいは下位帯より低くなるなど**非単調**な挙動が頻発 |
| ランダム50/50分割（9ファクター） | 時系列分割と同様に中間帯が不安定。ファクター数を5個・3個・2個に絞っても改善せず |
| ランダム分割・IDM順位単独 | IDM順位2〜3位は両フォールドで通常馬より高い回収率を維持し、方向性自体は安定。ただし絶対値の大きさ（学習期間中でも時期によって61%〜151%まで変動）は時期依存性が強い |

**結論：** 初装着(母集団7,012件)・再装着(同1,569件)という限られたサンプル数に対し9ファクターを合算する設計は、上位・下位の「極端」は安定して識別できるが、**スコアの中間の絶対値は過去データのノイズに強く影響されており、細かい大小に意味を持たせられない**。これはコース回収率指数で確認された「ファクター×コースの完全マトリクスは過学習する」という教訓と同根の問題で、こちらは「ファクター数 × 母集団の小ささ」が原因。

### 4.3 採用した設計：3段階グレード

上記の検証結果を踏まえ、**スコアの絶対値ではなく3段階のグレードのみを信頼できる出力とする**。

| グレード | 条件 | 意味 |
|---|---|---|
| **A** | score ≥ 30 | 高評価。学習・評価・ランダム分割のいずれでも通常馬を明確に上回ることを確認済み |
| B | -15 ～ 29 | 中立。積極的な根拠にはならない |
| C | score ≤ -16 | 低評価（ただし後述の通りBとの差は種別により一定しない） |

### 4.4 本番データでの実測（全期間、参考）

ETL実行後、`T_BLINKER_SCORE` を `T_ANALYZE_FACT` に結合して実測した結果：

| 区分 | グレード | 件数 | 勝率 | 単勝回収率 | 複勝回収率 |
|---|---|---:|---:|---:|---:|
| 初装着 | A | 2,109 | 7.0% | **145.4%** | 83.2% |
| 初装着 | B | 2,107 | 5.4% | 50.6% | 72.1% |
| 初装着 | C | 2,796 | 4.9% | 52.9% | 65.9% |
| 再装着 | A | 590 | 6.4% | **173.1%** | 99.4% |
| 再装着 | B | 204 | 4.9% | 48.4% | 49.0% |
| 再装着 | C | 775 | 3.5% | 32.2% | 80.9% |

**Aグレードは初装着・再装着とも通常馬（それぞれ約80%・87%）を大きく上回り、実用的な「買い」シグナルとして機能している。** 一方、**BとCの差は種別によって一致しない**（初装着はCがBよりわずかに高く、再装着はCがBより明確に低い）ため、**「C=積極的な回避」とまでは言い切れず、実質的には「A（高評価）かどうか」が主たる判断材料**であることが実データでも裏付けられた。

## 5. テーブル構成

### 5.1 T_BLINKER_FACTOR_AGG（ファクター別集計）

```sql
PRIMARY KEY (blinker_type, factor_type, factor_value)
```

`blinker_type` は `'1'`（初装着）・`'2'`（再装着）・`'ALL'`（プール、フォールバック用）。

### 5.2 T_BLINKER_SCORE（指数テーブル、blinker IN ('1','2') の馬のみ）

```sql
PRIMARY KEY (course_code, year_code, kai, day_code, race_num, uma_num)
```

| カラム | 説明 |
|--------|------|
| `blinker_type` | `1`:初装着 `2`:再装着 |
| `score` | 連続値スコア（§4の制約により絶対値は参考程度） |
| `grade` | **主たる出力**。`A`(高評価)/`B`(中立)/`C`(低評価) |
| `score_coursefit`〜`score_agari` | 各ファクターの寄与値（内訳、9種） |

## 6. ETLフロー

`sql/blinker_index.sql` の3パート構成：

```
Part 1: CREATE TABLE IF NOT EXISTS（T_BLINKER_FACTOR_AGG, T_BLINKER_SCORE）
Part 2: ファクター集計（初装着/再装着/プール × 9ファクター、TRUNCATE + INSERT）
Part 3: スコア計算・grade判定（T_BLINKER_SCORE、対象は blinker IN ('1','2') のみ）
```

`download.html` の「ブリンカー指数を更新する」ボタン、またはCLI：

```powershell
mysql -h localhost -P 3306 -u root -p racing < sql/blinker_index.sql
```

## 7. API

### POST /api/blinker-etl

ブリンカー指数 ETL を実行。SSEで進捗を返す。

### GET /api/factor-recovery

`blinkerIndex` フィールドに、初装着/再装着 × A/B/C グレード別の回収率集計を含む（`factor-recovery.html` で表示）。
