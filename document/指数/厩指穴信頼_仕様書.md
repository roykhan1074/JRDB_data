# 厩指穴信頼グレード 仕様書

> 最終更新: 2026-09-21
> ※ entries.html上の列名は「厩指穴信頼」（5文字のため`<br>`で「厩指穴」「信頼」の2行に手動改行）。DB上のテーブル名は`T_KYUSHA_*`。

---

## 1. 概要

**厩指穴信頼グレード**は、「厩舎指数がプラスかつ基準オッズが高い（穴馬寄りの）馬」というセグメントに限定したとき、**その馬の調教師が過去にどれだけ信頼できる成績を残しているか**を厩舎（調教師）単位でS〜Fの7段階に格付けした指標。

EX指数・本命指数・ブリンカー指数が「馬ごとにファクターの組み合わせでスコアを算出する」方式なのに対し、厩指穴信頼グレードは**調教師という単位で過去実績を格付けする**という点で設計思想が異なる（「厩舎指数（`T_KYI.kyusha_index`）という同じ数値でも、それを信頼して良い調教師とそうでない調教師がいる」という仮説の検証から生まれた）。

出馬表（entries.html）の「厩指穴信頼」列と、ウォッチリスト（watchlist.html）の抽出条件「厩指穴信頼ランク S〜B」に使用される。

---

## 2. 対象セグメントの定義（判定ゲート）

グレードが適用されるのは、**その馬自身が以下のセグメントに該当する場合のみ**（厩舎の総合グレードを無条件に全馬へ適用しない）。

| 条件 | 内容 |
|------|------|
| 厩舎指数 | `kyusha_index >= 0` |
| 基準オッズ | `kijun_odds >= 15` |
| サンプル数 | 該当調教師の対象セグメント内サンプル数 `n >= 20`（未満はグレード付けせず「—」表示） |

> オッズしきい値は当初の設計（`sql/kyusha_analysis_design.md`、2026年初頭）では10倍だったが、その後の検証で**15倍**に引き上げられている。`sql/kyusha_analysis_design.md`は初期設計のスナップショットであり、本書が現行の正典。

## 3. グレード判定ロジック

対象セグメント内の**複勝回収率**（`place_pay / n`）でグレードを決定する。境界値は下限を含む（左閉右開の逆、`>=`）。

| グレード | 複勝回収率 |
|---------|-----------|
| S | 130%以上 |
| A | 110%以上130%未満 |
| B | 100%以上110%未満 |
| C | 90%以上100%未満 |
| D | 80%以上90%未満 |
| E | 60%以上80%未満 |
| F | 60%未満 |

判定SQL（`src/server.ts`の`getTrainerGradeMap()`と`computeFactorRecovery()`内`kyushaRows`クエリで共通）:

```sql
WITH trainer_stats AS (
  SELECT trainer_code,
         COUNT(*) AS n,
         SUM(CASE WHEN ijou_kubun IN ('0','') THEN COALESCE(place_payout,0) ELSE 0 END) AS place_pay
  FROM T_KYUSHA_RACE_LOG
  WHERE kyusha_index >= 0 AND kijun_odds >= 15
  GROUP BY trainer_code
)
SELECT trainer_code,
  CASE
    WHEN (place_pay / n) >= 130 THEN 'S'
    WHEN (place_pay / n) >= 110 THEN 'A'
    WHEN (place_pay / n) >= 100 THEN 'B'
    WHEN (place_pay / n) >= 90  THEN 'C'
    WHEN (place_pay / n) >= 80  THEN 'D'
    WHEN (place_pay / n) >= 60  THEN 'E'
    ELSE 'F'
  END AS grade
FROM trainer_stats
WHERE n >= 20
```

> 厩舎指数の帯別（`kyusha_idx`）・穴セグメントの2×2マトリクス（`kyusha_idx_x_odds`）といった、より粒度の細かい集計テーブル `T_KYUSHA_FACTOR_AGG` も存在する（§5参照）。S〜Fグレードはこのうち `kyusha_idx_x_odds` の `plus_15~` セル（厩舎指数プラス×オッズ15倍以上）を調教師単位に集約したもの。

## 4. 表示ルール

### 4.1 entries.html（出馬表）

| 項目 | 内容 |
|------|------|
| 列名 | 厩指穴信頼（列#25、幅56px） |
| 表示条件 | この馬自身がセグメント該当（`kijun_odds>=15` かつ `kyusha_index>=0`）かつ調教師の`n>=20`の場合のみグレード文字を表示。非該当時は「—」 |
| セル背景色（`.kyt-*`） | S: 赤`#dc2626`文字白 / A: ピンク`#fbcfe8` / B: オレンジ`#f97316`文字白 / C: 黄色`#fef9c3` / D: なし / E: グレー`#e5e7eb`文字グレー / F: 濃灰`#374151`文字白 |
| ツールチップ | `全体数{n}件 / 単勝回収率{win_rr}% / 複勝回収率{place_rr}% / 勝率{win_rate}% / 複勝率{place_rate}%` |

> B（`#f97316`オレンジ）はCLAUDE.mdの配色規約（「アンバー・オレンジをC/Dに使うのは禁止」）の対象外（C/Dではない）だが、他のA〜Eグレード配色規約（赤=A系統/緑=B系統/薄グレー=E系統）とは異なる独自配色になっている点に注意。新規実装時にこの列を配色の参考にしない。

### 4.2 watchlist.html（ウォッチリスト）

抽出条件「厩信頼」タグ: グレードが `S`・`A`・`B` のいずれか（= 複勝回収率100%以上のセグメント）に該当する場合。凡例表示は「厩指穴信頼ランク S〜B（複勝回収率100%以上）」。

### 4.3 factor-recovery.html（指数帯別回収率）

グレード別（S〜F）に、該当調教師数・出走頭数・単勝/複勝回収率・的中率を集計して表示。「厩指穴信頼グレード別成績」セクション。

## 5. テーブル構成

### 5.1 T_KYUSHA_RACE_LOG（ファクトテーブル）

`T_KYI × T_BAC × T_SED` を結合した非正規化ログ。1行 = 1頭分の出走記録。

| カラム | 型 | 説明 |
|---|---|---|
| `trainer_code` | CHAR(5) | 調教師コード |
| `kyusha_index` | DECIMAL(5,1) | 厩舎指数（T_KYIのCHAR(5)から数値変換、不正値はNULL） |
| `kijun_odds` | DECIMAL(6,1) | 基準単勝オッズ |
| `finish_order` | CHAR(2) | 着順 |
| `win_payout` / `place_payout` | INT | 単勝・複勝払戻（円、異常区分以外） |

### 5.2 T_KYUSHA_FACTOR_AGG（ファクター別集計、EAV形式）

PRIMARY KEY `(trainer_code, agg_year, factor_type, factor_value)`。主な`factor_type`:

| factor_type | 内容 |
|---|---|
| `kyusha_idx` | 厩舎指数帯（6段階: `<-10`/`-10~0`/`0~10`/`10~20`/`20~30`/`30~40`） |
| `kyusha_idx_x_odds` | 厩舎指数符号 × オッズ帯の2×2マトリクス。`plus_15~`セルが本グレードの元データ |

> S〜Fグレードは`T_KYUSHA_RACE_LOG`から都度SQLで集計する方式であり、EX指数・本命指数・ブリンカー指数のような専用スコアテーブル（`T_*_SCORE`）は持たない。

## 6. ETLフロー

`sql/kyusha_analysis.sql`（2パート構成、Part2・3は差分投入可・冪等）:

```
Part 1: CREATE TABLE IF NOT EXISTS（T_KYUSHA_RACE_LOG, T_KYUSHA_FACTOR_AGG）
Part 2: INSERT INTO T_KYUSHA_RACE_LOG（T_KYI×T_BAC×T_SED、ON DUPLICATE KEY UPDATE）
Part 3: INSERT INTO T_KYUSHA_FACTOR_AGG（factor_type別集計、ON DUPLICATE KEY UPDATE）
```

### 実行方法

**他の指数（EX/本命/ブリンカー）と異なり、download.html にETL実行ボタンは存在しない。** CLIから直接実行する。

```powershell
mysql -h localhost -P 3306 -u root -p racing < sql/kyusha_analysis.sql
```

実行後、`getTrainerGradeMap()`のキャッシュ（`trainerGradeCache`）をクリアする必要がある。`POST /api/factor-recovery/refresh` を叩くとキャッシュがクリアされ、ウォッチリスト・出馬表双方のグレードが再計算される（`src/server.ts`のコメント「ウォッチリストの厩指穴信頼グレードも合わせて再計算させる」参照）。

### 推奨実行タイミング

| タイミング | 理由 |
|-----------|------|
| 毎週木曜日 | T_SED（成績速報）の正式版が木曜日に確定するため |

## 7. API

厩指穴信頼専用のETL APIは存在しない。以下のAPIがグレード計算・キャッシュを内包する。

### GET /api/races/:raceKey/entries

`T_KYUSHA_FACTOR_AGG`の`kyusha_idx_x_odds`/`plus_15~`セルをtrainer_code単位に集約したサブクエリをLEFT JOINし、`kyusha_anaba_place_rr`等を返却（entries.htmlはこれを元に自前でS〜F判定する）。

### GET /api/watchlist?ymd=YYYYMMDD

`getTrainerGradeMap()`（メモリキャッシュ、`trainerGradeCache`）で全調教師のグレードを事前計算し、対象セグメント該当馬に適用。

### GET /api/factor-recovery

`computeFactorRecovery()`内でグレード別の回収率集計（`kyushaRows`）を行い、`factorRecoveryCache`にキャッシュ。

### POST /api/factor-recovery/refresh

上記キャッシュと`trainerGradeCache`を両方クリアして再計算。
