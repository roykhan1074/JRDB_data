# 複勝100複合シグナル 仕様書

> 最終更新: 2026-09-21
> ※ UI上の表示名は「複勝回収率100%超シグナル」（entries.html🎯マーク）／「複勝100」（watchlist.htmlタグ）。単一の指数値ではなく、7つのフラグを合算した0〜7点のスコア`sc`と、それをオッズ帯でフィルタする複合ルールである点が他の指数（EX指数・本命指数・ブリンカー指数）と異なる。

---

## 1. 概要

複数のJRDBファクターが同時に揃い、かつ市場が「人気薄だが見放されてはいない」と評価している馬（基準オッズ15〜30倍）に絞り込むと、**複勝回収率が100%を超える**という検証結果に基づく複合シグナル。

出典: `document/分析レポート/複勝回収率100%超_統合理論レポート.md`。学習期間（2020/01〜2023/12）と評価期間（2024/01〜2026/08、真のOut-of-Sample）の両方で複勝回収率100%前後を再現しており、7年連続で87〜121%のレンジに収まる（単年度で崩れないことを確認済み）。

出馬表（entries.html）では該当馬の馬名セルに🎯マークとツールチップで表示され、行が`fukusho-signal`クラスでハイライトされる。ウォッチリスト（watchlist.html）では「複勝100」タグとして表示される。

---

## 2. シグナル設計（sc スコア）

以下7つのフラグ（各1点）を合算したスコア`sc`（0〜7）を算出する。**すべてのフィールドは出馬表時点（レース前）で判定可能な値**であり、結果テーブル（T_SED）には依存しない。

| フラグ | 条件 | 根拠 |
|---|---|---|
| `scIdx` | `EX指数(全体)≥15` OR `本命指数(全体)≥10` | EX指数/本命指数の基礎閾値 |
| `scIdxStrong` | `EX指数(全体)≥50` OR `本命指数(全体)≥30` | 同、上位閾値 |
| `scCombo` | 騎手×調教師の複勝回収率（`T_COMBO_RECOVERY.place_recovery`）が100%以上、かつサンプル数`combo_n≥30` | 既存T_COMBO_RECOVERY相当 |
| `scChokyo` | `oi_index≥70` OR `shiage_index≥70`（追切指数・仕上指数） | 調教充実度 |
| `scGoal` | `goal_juni` が1位または2位 | 展開予測上位 |
| `scJoho` | 情報指数のレース内順位（0・NULLおよび非開示`-1`を除外した上でのdense rank）が1位または2位 | 取材情報の上位評価 |
| `scTa` | `ten_index_juni=1` OR `agari_index_juni=1` | テン指数/上がり指数トップ |

```
sc = scIdx + scIdxStrong + scCombo + scChokyo + scGoal + scJoho + scTa
```

### 実装上の注意（Look-ahead回避）

`scCombo`（騎手×調教師の複勝回収率）は、**予想対象レースより後のデータを含めて集計してはならない**という前提でレポートは検証されている。現行実装（`T_COMBO_RECOVERY`）が「その時点までの実績のみ」で運用されているかは、本レポート内で「実装時に必ず確認すること」と明記されており未確認事項として残っている（§7参照）。

## 3. 発火条件（sc ≥ 3 × 基準オッズ15〜30倍）

**条件: `sc ≥ 3` かつ `15 ≤ 基準オッズ < 30`**

| 期間 | n | 複勝回収率 | 複勝的中率 |
|---|---:|---:|---:|
| 学習期間（2020/01〜2023/12） | 1,675 | 101.1% | 19.3% |
| 評価期間 2024年のみ | 440 | 110.9% | 21.4% |
| 評価期間 2025〜2026年 | 708 | 100.5% | 20.9% |
| **全期間合計** | **3,523** | **100.7%** | **20.0%** |

7年中5年が100%超・2年（2020, 2021）が87〜91%で、赤字年でも大幅マイナスにはならない。芝・ダート双方でほぼ同水準（芝101.3%／ダート100.0%）で、特定コース・馬場への依存はない。詳細な年度別内訳・オッズ帯別の比較（なぜ15〜30倍が機能するのか）は元レポート第3章を参照。

### なぜ15〜30倍なのか

同じ`sc≥3`条件で他のオッズ帯を見ると、1〜15倍帯では市場が既に効率的（複勝回収率83〜85%止まり）、30倍以上は荒れすぎてサンプルも不安定（79.4%）。「JRDB指数だけで能力は高いと分かるが、+2つ以上の補強シグナルが同時に揃って初めて、市場が15〜30倍に評価している馬の中に本当の割安馬を見分けられる」ゾーンが15〜30倍という結論（元レポート3-5節）。

## 4. 重要な注意事項（過信してはいけない理由）

### 4.1 回収率は少数の高配当に依存する

`sc≥3 × 15〜30倍`（n=3,523）から的中した中で配当が最も高い上位35件（全体の1%）を除外すると、複勝回収率は100.7%→**83.2%**まで低下する。**「毎回当てて安定して100%を超える」わけではなく**、約20%の確率で的中し、その大半は堅めの配当だが、ごく稀に複勝配当1,000円を超える大穴的中が混じることで平均が押し上げられている（最大配当6,160円のケースあり）。機械的に多数（年間数百点以上）を均等額でベットし続けて初めて期待値が収束する。単発・少数レースでの検証では100%超を実感できない期間の方が長い。

### 4.2 安定性重視パターン（参考）

回収率よりも的中頻度を重視する場合、`sc≥4 かつ 基準オッズ<2倍`で複勝的中率90%前後・複勝回収率95%前後（100%にわずかに届かない）というトレードオフパターンも存在する（元レポート第5章）。現行のentries.html/watchlist.html実装は回収率重視パターン（sc≥3×15〜30倍）のみを実装しており、安定重視パターンは未実装。

## 6. 実装（サーバー側ロジック）

専用のETL・スコアテーブルは持たない。`GET /api/races/:raceKey/entries`（entries.html用）と`GET /api/watchlist`（watchlist.html用）それぞれで、リクエスト時にJavaScript側で同一ロジックを再計算している（≒ロジックが2箇所に重複実装されている）。

```javascript
const scIdx        = (exOverall >= 15 || honmeiOverall >= 10) ? 1 : 0;
const scIdxStrong   = (exOverall >= 50 || honmeiOverall >= 30) ? 1 : 0;
const scCombo       = (comboN >= 30 && comboRr >= 100) ? 1 : 0;
const scChokyo      = (oiIdx >= 70 || shiageIdx >= 70) ? 1 : 0;
const scGoal        = (goalJuni === 1 || goalJuni === 2) ? 1 : 0;
const scJoho        = (johoRank === 1 || johoRank === 2) ? 1 : 0;  // 0/NULL/-1除外後のdense rank
const scTa          = (tenJuni === 1 || agariJuni === 1) ? 1 : 0;
const scTotal       = scIdx + scIdxStrong + scCombo + scChokyo + scGoal + scJoho + scTa;
const isFukushoSignal = scTotal >= 3 && odds >= 15 && odds < 30;
```

- `src/server.ts`: `/api/watchlist`ハンドラ内（`matchFukusho100`変数）
- `public/entries.html`: 行生成ロジック内（`isFukushoSignal`変数）

両実装のロジックが将来ズレないよう、いずれかを修正した場合はもう一方も必ず同時に修正すること。
