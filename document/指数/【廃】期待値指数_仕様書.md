## 1. 概要

**期待値指数**は、機械学習モデル（`HistGradientBoostingClassifier`）による予測複勝確率（オッズ帯別に較正済み）が、市場（複勝オッズ）が織り込む複勝確率よりどれだけ高いかを数値化した指数。用途は「軸/消し」の判断材料であり、単体で単勝・複勝の回収率100%超を保証するものではない（詳細は§5・§9）。

---

## 2. 対象馬の定義

| 項目 | 定義 |
|------|------|
| 対象 | `T_BAC.tds_code IN ('1','2')`、`class <> 'A1'` の全レースの全出走予定馬 |
| スコア付与条件 | `T_KYI.kijun_fukusho_odds`（基準複勝オッズ）が有効な馬のみ（オッズ0または未設定の馬はスコアなし） |
| 結果確定前でもスコア付与 | 学習は過去の確定済みレースのみで行うため、まだ結果が出ていない出走予定レースの馬にも本指数が付与される |

## 3. 指数の仕組み

### 3.1 モデル

`HistGradientBoostingClassifier`（scikit-learn）による二値分類モデル。目的変数は複勝的中（`finish_order <= 3`）。

```python
MODEL_PARAMS = dict(
    max_iter=300, max_depth=4, learning_rate=0.04, min_samples_leaf=200,
    l2_regularization=1.0, validation_fraction=0.15, n_iter_no_change=20, random_state=42,
)
```

`min_samples_leaf=200` が小サンプル過学習に対するガード。カテゴリ特徴量は `categorical_features` で指定し、モデルに交互作用の自動探索を任せる。

### 3.2 使用ファクター

| 種別 | フィールド |
|---|---|
| カテゴリ（12種） | `course_code`, `tds_code`, `kyakushitsu`, `joshodo`, `kyori_tekisei`, `omo_tekisei`, `dirt_tekisei`, `shiba_tekisei`, `chokyo_yajirushi`, `kyusha_hyoka`, `blinker`, `waku_num` |
| 数値（13種） | `distance`, `ten_index_juni`, `agari_index_juni`, `ichi_index_juni`, `goal_juni`, `idm`, `gekiso_index`, `manbaken_index`, `heads`, `joho_index`, `kyusha_index`, `oi_index`, `shiage_index` |

欠損値の扱い：順位系は「最下位扱い」として`99`で埋める、指数系は`0`埋め（`joho_index`の`-1`＝情報非開示は特別な意味を持つ値のため潰さず保持）、頭数は中央値埋め、カテゴリは`"NA"`文字列化。`oi_index`/`shiage_index`は`T_CYB`（調教印テーブル）からLEFT JOINで取得（未計測馬は欠損扱い→0埋め）。

**`joho_index`・`kyusha_index`・`oi_index`・`shiage_index`の追加経緯（2026-09-27）：** 初期実装ではこの4特徴量が未使用だった。CLAUDE.md「買い目推奨時の分析方針」が明記する主要ファクターと実際の特徴量リストを突き合わせて漏れを発見し、追加した。ウォークフォワード検証（2020-2023学習/2024-2026検証）で以下の改善を確認済み。

| 指標 | 追加前 | 追加後 |
|---|---:|---:|
| AUC | 0.7850 | 0.8015 |
| Brier Score | 0.1366 | 0.1332 |
| LogLoss | 0.4276 | 0.4161 |
| 予測率50%+帯の実測複勝率 | 61.2% | 62.2% |
| 予測率15%未満帯の実測複勝率 | 7.7% | 6.8% |

上位帯はより実測が高く、下位帯はより実測が低くなり、「指数が高いほど当たりやすく・低いほど外れやすい」という分離が改善した。新しい特徴量を追加する際は、既存のドメイン知識（CLAUDE.mdの主要ファクター一覧）と実際に使っている特徴量リストを突き合わせて漏れがないか確認することが今後も有効。

### 3.3 オッズ帯別isotonic較正（重要）

モデルの生の予測確率は、**基準複勝オッズ帯によって系統的にミスキャリブレーションする**（人気薄の馬ほど「当たる」と予測しすぎる）。これを放置すると期待値計算（後述）が穴馬側で意味のない超高値を出す。この歪みを補正するため、以下の手順で較正する。

1. 学習データに対し5-fold `cross_val_predict`でout-of-fold予測を取得する。
2. 基準複勝オッズを8帯（`~1.5 / 1.5-2 / 2-3 / 3-5 / 5-8 / 8-15 / 15-30 / 30+`）に分割する。
3. オッズ帯ごとに別々の`IsotonicRegression`較正器を（out-of-fold予測 → 実際の複勝結果）でfitする（各帯n<200の場合はその帯の較正をスキップし生の予測値を使う）。
4. 採点対象馬の予測確率を、その馬の基準複勝オッズが属する帯の較正器で変換する。これが`pred_place_prob`（較正後）になる。

### 3.4 指数の計算式

```
pred_place_prob   = オッズ帯別較正後の予測複勝確率（0〜1、[0.01, 0.95]にクリップ）
market_place_prob = 1 / 基準複勝オッズ（市場が織り込む複勝確率）
ev_raw            = (pred_place_prob / market_place_prob − 1) × 100
ev_index          = ev_raw を [-100, 50] にクリップ。ただし ev_raw >= 50 の行は
                     ev_index・pred_place_prob を NULL 化し「対象外」（空白セル）にする
race_rank         = pred_place_probをレース内で高い順に順位化したもの（1=最有力）
race_rank_from_last = 同、下位からの順位（1=最下位）
```

プラスが大きいほど「モデルは市場より高く評価している＝過小評価されている＝妙味がある」、マイナスが大きいほど「市場の方が高く評価している＝過大評価されている」ことを意味する。

**データ品質ガード（2026-09-27追加）：**
- 基準複勝オッズに`90`以上の値（JRDBの「999.9」等のセンチネル値を含む）が入っている場合はNULL（欠損）扱いにする。実データで309,024件中45件が`999.9`という「データなし」を表す特殊値で、これを実オッズとして扱うと期待値比率が桁違いに暴走することが判明したため。
- `pred_place_prob`を`[0.01, 0.95]`にクリップ。学習サンプルが薄いオッズ帯で`IsotonicRegression`がちょうど`0.0`/`1.0`（＝複勝確定/複勝絶望という非現実的な断定）を出力することがあるため。
- `ev_raw >= 50`の行はスコア自体をNULL化する（対象外）。基準オッズ30倍以上の帯は較正器の学習サンプルが薄く、粗い階段状の出力を極小の市場確率で割ることで期待値比率が桁違いに増幅されるケースがあり（実データで较正後も+1000%超えを複数確認）、かつウォークフォワード検証でこの集団(n=28)は複勝回収率27.1%と検証済みの上位帯(82〜86%)より明確に悪いことを確認した。**値を単にクリップするだけでは「最上位」の色分類に留まり続けて実質的に直らないため、スコアそのものをNULL化して表示上「対象外」にする**（本番実績で117件/273,940件が該当）。

### 3.5 表示値のシフト（重要）

出馬表に表示する値は`ev_index`そのものではなく、**`ev_index + 25`**である（DB上の`ev_index`・色分け閾値は変更していない。表示層のみのシフト）。

理由：`ev_index`の「0」は数式上「モデルの予測確率と市場想定確率が一致する点」に過ぎず、この母集団の実測加重平均複勝回収率（71.2%）とは無関係である。そのため、実際には母集団平均より複勝回収率が高い`-20~-5`帯（実測81.3%）がマイナス表示になり、「回収率は平均より良いのに指数はマイナス」という違和感を生んでいた。`+25`シフトにより「0 ≈ 平均的な回収率（75%前後）」となるよう表示のみ再定義し、プラス/マイナスの符号が「平均より良い/悪い」という直感と一致するようにしている。

## 4. 先読みバイアス防止の設計

CLAUDE.md「指数/スコアETL実装時の必須チェック」に基づき、以下を徹底している。

- **学習用データ**：`T_KYI × T_BAC × T_SED`（結果が確定した過去レースのみ、`INNER JOIN T_SED` で結果未確定の行は学習に含まれない）
- **採点対象データ**：`T_KYI × T_BAC` のみ（`T_SED` を一切参照しない）。これにより結果未確定の出走予定レースにもスコアが付与される一方、そのレース自身の結果がスコアに混入することは構造的に起こらない。
- オッズ帯別較正器も学習データのout-of-fold予測のみで`fit`し、採点データには適用（`predict`）のみ行う。
- カテゴリエンコーダ（`OrdinalEncoder`）は学習データで `fit` し、採点データには `transform` のみ適用。

| ~1.5倍 | 67.6% | 67.6% | ±0.0pt |

| 15-30倍 | 1.7% | 1.9% | +0.1pt |

| 指標 | 数値 |
|---|---:|
| n | 8,165レース |
| 実測複勝率 | 47.7% |
| 複勝回収率 | 84.1% |
| 単勝回収率 | 82.5% |

基準人気の内訳は1番人気37.8%・2番人気13.7%・3番人気6.4%・4-5番人気11.2%・6-8番人気13.1%・9番人気以下18.7%であり、人気馬だけでなく人気薄馬も一定割合選ばれている（生の予測複勝確率だけで順位付けした場合は9番人気以下が0%だった）。

## 7. ETLフロー

`python/ev_index_etl.py`（Python版、mysql.connector使用）：

```
Step1: 学習データ取得（T_KYI×T_BAC×T_SED、結果確定済みのみ、基準複勝オッズ含む）
Step2: 採点母集団取得（T_KYI×T_BAC、結果未確定含む全馬）
Step3: HistGradientBoostingClassifierで学習
Step3b: 5-fold out-of-fold予測 → オッズ帯別isotonic較正器を学習
Step4: 採点母集団全馬を較正込みでスコアリング、レース内順位を計算
Step5: T_EV_SCORE_NEWへ書き込み → RENAME TABLEで原子的差し替え
```

「別名で新規構築→完成後に原子的にRENAMEで差し替え」方式（クラッシュ耐性）。オッズ帯別較正の追加により、以前(1〜2分)より所要時間が伸びる（5-fold分の追加学習のため）。

## 9. 現状のスコープと注意点

- 本指数は「そのレース内での相対的な期待値の高さ」を前提に設計・検証されている。population全体を通じた絶対的な閾値としての単勝・複勝回収率100%超の保証は行っていない（§5.2・5.3参照）。
- 基準複勝オッズが未設定・0・センチネル値（90倍以上）の馬にはスコアが付与されない（表示は空欄）。
- **`ev_raw`が+50以上の馬もスコア対象外（NULL、表示は空欄）。** ウォークフォワード検証でこの集団(n=28)は複勝回収率27.1%と明確に悪く、「最上位」として表示するのは誤りと判断したため、値をクリップするのではなくNULL化している（本番実績で117件/273,940件が該当、§3.4参照）。
- モデルは複勝的中を目的変数としており、単勝的中や着順そのものの予測ではない。
- オッズ帯別較正器は各帯n≧200を要求する。学習データがこの閾値を満たさない帯（通常は発生しない想定）は較正をスキップし生の予測値を使う。
- `model_version`（ETL実行日）はモデルの再学習日を示すのみで、学習データの参照範囲は`fetch_training_data()`のクエリ条件に従う（現状は全期間の確定済みレースを使用、期間絞り込みは未実装）。
