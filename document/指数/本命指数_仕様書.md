# 本命指数 仕様書

> 最終更新: 2026-09-21

---

## 1. 概要

**本命指数**は、EX指数（旧穴馬指数）と対になる指数で、JRDBの各種ファクターを組み合わせて「本命サイドの馬（基準オッズ10倍未満）がどれだけ堅実に走る期待値を持つか」を数値化したもの。

出馬表（entries.html）の `本命` 列（本命指数コース）に表示されるほか、ウォッチリスト（watchlist.html）の抽出条件「一番人気以外×本命指数(コース)≧50」にも使用される。

EX指数が「穴馬（オッズ≧10倍）の激走期待値」を測るのに対し、本命指数は「人気馬（オッズ<10倍）の信頼度」を測る、いわば対の指数である。

---

## 2. 対象馬の定義

| 項目 | 定義 |
|------|------|
| ETL対象 | `kijun_odds > 0 AND kijun_odds < 10.0` の馬のみ `T_HONMEI_RACE_LOG` に格納 |
| スコア計算 | **出走全馬**（`T_HONMEI_SCORE`）に対して算出 |
| 表示時の色付け | `kijun_odds > 0 AND kijun_odds < 10.0` の馬のみ色を付ける（entries.htmlの`isHonmei`判定） |
| 非対象ETL | 障害レース（`tds_code='3'`は`T_HONMEI_RACE_LOG`投入時点で除外。`tds_code IN ('1','2')`のみ対象）、新馬戦（`class='A1'`） |

EX指数と同様、本命指数はオッズ10倍未満の馬に対してのみ意味を持つ設計のため、10倍以上の馬には表示・色付けを行わない。

---

## 3. 指数の仕組み

### 3.1 基本思想

EX指数と同一の計算方式。過去データから「このファクター値を持つ本命サイドの馬は平均よりどれだけ多く回収できるか」を測り、その偏差を合算してスコアとする。

```
指数スコア = Σ（各ファクターの単勝回収率 − ベースライン単勝回収率）
```

- **ベースライン**: 全本命サイド馬（`kijun_odds > 0` かつ `< 10.0`）の平均単勝回収率
- **各ファクタースコア**: そのファクター値を持つ本命サイド馬の回収率とベースラインの差（単位: %ポイント）

### 3.2 指数の種類

| 指数 | 説明 | APIフィールド |
|------|------|-------------|
| 本命指数（全体） | 全競馬場・全距離のデータで算出 | `honmei_overall_score` |
| 本命指数（コース別） | 場コード×芝ダ×距離帯で補正 | `honmei_course_score` |

## 4. 使用ファクター一覧

EX指数とほぼ共通の展開系ファクターに加え、本命指数は**能力系ファクターとしてIDM・情報指数・厩舎指数**を用いる点がEX指数（激走系の激走指数・万券指数を用いる）と異なる。「堅実に走るか」を測る指数のため、実力の絶対値を示す指標を重視する設計。

### 4.1 展開系（コース別対応あり）

| ファクター種別 | テーブル/カラム | 分類帯 | コース補正 |
|-------------|---------------|--------|---------|
| テン指数順位 | `T_KYI.ten_index_juni` | 1位 / 2〜3位 / 4〜6位 / 7位以下 | 場×芝ダ×距離帯 |
| 上がり指数順位 | `T_KYI.agari_index_juni` | 1位 / 2〜3位 / 4〜6位 / 7位以下 | 場×芝ダ×距離帯 |
| 位置指数順位 | `T_KYI.ichi_index_juni` | 1位 / 2〜3位 / 4〜6位 / 7位以下 | 場×芝ダ×距離帯 |
| ゴール順位 | `T_KYI.goal_juni` | 1位 / 2〜3位 / 4〜6位 / 7位以下 | 場×芝ダ×距離帯 |
| 複合展開パターン | `ten_index_juni` × `agari_index_juni` × `ichi_index_juni` の組合せ | EX指数と同じ4種＋other（`dual_top`/`sen_oki`/`hana_iki`/`mid_chaser`） | 場×芝ダ×距離帯 |

### 4.2 能力指数系（全体のみ・本命指数固有）

| 厩舎指数帯 | `T_KYI.kyusha_index` | `kyusha_band`（本命専用ファクター） |

### 4.3 調教・馬質系（全体のみ）

| ファクター種別 | テーブル/カラム | 分類 |
|-------------|---------------|------|
| 調教評価 | `T_CYB.chokyo_hyoka` | A / B / C / D / E |

| 距離適性 | `T_KYI.kyori_tekisei` | A / B / C / D 等 |

| ファクター種別 | テーブル/カラム | コース補正 |

| 母父系統コード | `T_UKC.hahachichi_keitou_code` | 芝ダ別 |

## 5. スコアの読み方

### 5.1 出馬表での配色ルール（絶対値ベース、`kijun_odds<10`の馬のみ・entries.htmlの`honmeiBg`）

EX指数と同じ色系（ピンク/黄色/グレー）を踏襲しつつ、しきい値は本命サイド用に調整している。

| スコア | セル背景 | 備考 |
|--------|---------|------|
| 50以上 | 薄赤 `#f87171` | |
| 30〜49 | ピンク `#fbcfe8` | |
| 15〜29 | 黄色 `#fef9c3` | |
| 0〜14 | なし（白） | |
| 0未満 | グレー `#e5e7eb` | |

> EX指数（§5.1）のような全スコア帯別の単独バックテスト表は本命指数には存在しない。ただし `複勝回収率100%超_統合理論レポート.md`（3-1節 `idx_flag`/`idx_strong`）で `honmei_overall_score ≥ 10` / `≥ 30` の2つのしきい値が複合シグナルの構成要素として実際に回収率改善に寄与することが評価期間で確認されている。単独指数としての帯別回収率検証は今後の課題。

### 5.2 ウォッチリストでの使用（watchlist.html）

抽出条件「本命」タグ: `一番人気以外 × honmei_course ≥ 50`（一番人気は指数に関わらず売れるため意図的に除外）。

### 5.3 全体指数 vs コース別指数

EX指数と同じ考え方（§3参照）。コース別データが少ない場合（HAVING COUNT(*) < 20 相当）はフォールバックして全体値を使用。

## 6. テーブル構成

### 6.1 T_HONMEI_RACE_LOG（ファクトテーブル）

`kijun_odds > 0 AND kijun_odds < 10.0` の馬のみ格納。PRIMARY KEY はEX指数と同じレースキー構成。

### 6.2 T_HONMEI_FACTOR_AGG（ファクター別集計、EAV形式）

PRIMARY KEY `(factor_type, factor_value, course_code, tds_code, dist_band)`。

### 6.3 T_HONMEI_SCORE（指数テーブル、出馬表表示用）

| カラム | 説明 |
|--------|------|
| `overall_score` | 本命指数（全体）DECIMAL(7,1) |
| `course_score` | 本命指数（コース別）DECIMAL(7,1) |
| `score_ten`〜`score_blood` | 各ファクターの寄与値（内訳） |
| `score_ten_c`〜`score_blood_c` | コース別内訳（データのある5ファクターのみ別列。残り6ファクターはoverall側と同値のため列を共有） |

> T_HONMEI_SCORE は **出走全馬** を対象に計算する（指数が意味を持つのはオッズ10倍未満の馬のみで、表示側でフィルタする）。

## 7. ETLフロー

`sql/honmei_index.sql` の4パート構成（EX指数と同じPart構成）：

```
Part 1: CREATE TABLE IF NOT EXISTS（T_HONMEI_RACE_LOG, T_HONMEI_FACTOR_AGG, T_HONMEI_SCORE）
Part 2: INSERT INTO T_HONMEI_RACE_LOG（kijun_odds>0 かつ <10 の馬のみ）
Part 3: INSERT INTO T_HONMEI_FACTOR_AGG（14ファクター × 全体+コース別）
Part 4: INSERT INTO T_HONMEI_SCORE（全馬対象）
```

### 実行方法

`download.html` の「本命指数を更新する」ボタン、またはCLI：

```powershell
mysql -h localhost -P 3306 -u root -p racing < sql/honmei_index.sql
```

> **注意（クラッシュ耐性未対応）**: `sql/anaba_index.sql`・`sql/blinker_index.sql`・`sql/course_recovery_index.sql` は「別名で新規構築→RENAMEで原子的差し替え」方式に対応済みだが、本ファイル（`sql/honmei_index.sql`）はPart4が `ON DUPLICATE KEY UPDATE` によるUPSERT方式のままで、この対策は未対応。ETL実行中に中断した場合、T_HONMEI_SCOREが部分更新の状態で残る可能性がある（詳細はCLAUDE.mdの「指数/スコアETL実装時の必須チェック」参照）。

## 8. API

### POST /api/honmei-etl

本命指数 ETL を実行。SSEで進捗を返す。

### GET /api/races/:raceKey/entries

T_HONMEI_SCORE を LEFT JOIN し `honmei_overall_score`、`honmei_course_score`、`hms_score_*`（内訳13種）を返却。

### GET /api/watchlist?ymd=YYYYMMDD

T_HONMEI_SCORE を LEFT JOIN し、`honmei_course ≥ 50 AND kijun_ninki ≠ 1` の馬を `match_honmei: true` として抽出。

## 9. 表示位置

### entries.html（出馬表）

```
枠 | 馬番 | ... | B | EX指数(コース) | 本命(コース) | 脚質 | オッズ | ...
```

```

```

### watchlist.html（ウォッチリスト）

条件該当馬の一覧テーブルに `本命指数` 列として表示。該当条件列に「本命」タグを表示。
