# 一変シグナル 仕様書

- 2026-10-11 作成、2026-10-12 更新（A/B表示・指数帯別回収率ページのパネル追加・運用）。
- 表示場所: 出馬表（entries.html）列#9「一変」、指数帯別回収率（factor-recovery.html）の「一変シグナル」パネル。

## 1. 目的

前走から状況が変わって、穴馬が一変しうる材料を数えて表示する。

- sc（注目馬複合シグナル）とは**別に運用**する（sc の点数には入れない）。
- **単体で回収率100%超えを狙うものではなく、「気づき」の一助**（ユーザー判断）。
- 「消し」や「sc上位の割引」には使わない（ユーザー判断。プラスの材料としてだけ使う）。

## 2. 要素（12種）

すべてレース前に分かる情報だけを使う（今走の T_KYI/T_BAC、前走の T_KYI/T_SED、今走より前の T_SED）。

| # | 要素 | 定義 | 理論的な根拠 |
|---|---|---|---|
| 1 | 前走ハイペースを先行して6着以下 | 前走 T_SED.race_pace='H' かつ race_kyakushitsu が 1/2 かつ 6着以下 | 展開で潰れただけ |
| 2 | 前走4角で外を回って4着以下 | 前走 corner_4_posi が 4/5 かつ 4着以下 | コースロス |
| 3 | 前走で不利(2段階以上) | 前走 furi/mae_furi/naka_furi/ushiro_furi の最大が2以上 | 敗因がはっきりしている |
| 4 | 前走がハイレベル戦で4着以下 | 前走の同走馬（自分以外）が前走の後に走った最初のレースのうち、**今走の日付より前のもの**が5頭以上あり、その3着内率が40%以上。かつ前走4着以下 | 強い相手に負けただけ |
| 5 | 実績のある芝ダに戻る | 今走より前に今回と同じ芝ダで3着内あり、かつ前走は別の芝ダ | 適性外からの巻き返し |
| 6 | 実績のある距離に戻る(前走6着以下) | 今走より前に同じ芝ダ×同じ距離帯（200m刻み）で3着内あり、かつ前走6着以下 | 適性条件での巻き返し |
| 7 | 実績のある回りに戻る(前走逆回りで6着以下) | 今走より前に同じ回りで3着内あり、かつ前走は回りが違って6着以下 | 苦手な回りだっただけ |
| 8 | ハンデ戦で斤量2kg以上減 | 今走がハンデ戦（T_BAC.weight='1'）かつ 今走斤量−前走斤量 ≤ −2kg（斤量は0.1kg単位で保存） | 相手より有利になる |
| 9 | 外厩明け(中8〜11週×放牧先A) | T_KYI.rotation 8〜11 かつ hohbokusaki_rank='A' | 外厩で仕上げた休み明け |
| 10 | 厩舎指数+10〜20良化(前走6着以下) | 今走の厩舎指数−前走時の厩舎指数（前走の T_KYI）が+10以上+20未満、かつ前走6着以下 | 陣営の評価が上向いた |
| 11 | 前走が稍重 | 前走 baba_cond の1桁目が2 | 力を出しにくい馬場だった |
| 12 | 距離200m以上短縮 | 今走距離−前走距離 ≤ −200m | 脚が持たなかった馬が楽になる |

- 3着内 = 異常区分が正常（0 または空）で着順1〜3。前走 = T_KYI.prev1_seiseki_key（血統登録番号＋前走年月日）で引く T_SED の行。
- 対象外: 障害レース、前走が JRA の成績に無い馬（新馬・地方/海外帰り等）。

### 2.1 効かなかった候補（採用しない）
市場が先に評価していてプラスにならなかったもの（2021〜2026の下見、穴馬）: 前走で上がり3F上位なのに負けた、着差0.3秒以内の惜敗、前走IDM上位で負けた、2走前好走→前走凡走、前走スローを差して負けた、情報指数の良化、叩き2・3戦目、芝→ダ替わり。

## 3. 表示

### 3.1 出馬表（列#9「一変」、48px）
| 表示 | 条件 | 色 | 1レースあたり |
|---|---|---|---|
| **A** | 4個以上 | ピンク `#fbcfe8` | 0.67頭 |
| **B** | 3個 | 黄色 `#fef9c3` | 1.29頭 |
| 空欄 | 2個以下・対象外 | なし | — |

- マウスを乗せると個数と当てはまった要素を表示（data-tip）。
- B の色は A〜E グレード規約（B=薄緑）ではなく、**ユーザー指定の黄色**（2026-10-12）。
- 色は `ippenBg()`（entries.html、scBg と同じ形）。
- A がいるレースは約4割、A か B がいるレースは約7割5分（2022〜2026、平均13.8頭立て）。

### 3.2 指数帯別回収率ページ（パネル `panel-ippen`）
A / B / 2個 / 1個 / 0個 別の成績を、全馬と穴馬（基準10倍以上）の2つの表で表示（4.2 の値）。検証済みの固定値なので「再集計」ボタンでは更新されない。値の生成は `python/research/gen_ippen_table.py`（前提: `ippen_plus_wf.py` の出力）。

## 4. 検証

### 4.1 要素の選び方（walk-forward、`python/research/ippen_plus_wf.py`）
概念ごとにしきい値の候補を持ち、毎年 Y について Y年より前の穴馬（基準10倍以上）で「複勝の同オッズ帯平均との差が+3pt以上、かつ前の年のうちマイナスの年が1年以下」の最良候補を採用する。2026年時点の採用結果を固定ルールにしたのが上の12要素。
下見で効かなかった候補も混ぜて選ばせた版（`POOL=full`）でも、選ばれる要素はほぼ同じだった。

## 5. 運用

- **専用の集計テーブルも ETL も無い。** 出馬表を開いた時点で、API が T_KYI・T_BAC・T_SED から計算する。指数の更新ボタンは不要。
- 毎週の「ダウンロード＆DB取込」（出馬表と成績）だけで表示される。2026-10-11（成績未取込の開催日、344頭）で A 15頭・B 27頭が表示されることを確認済み。
- **前の週の成績（SED）が未取込だと**、先週走った馬は前走が見つからず対象外（空欄）になる。また「前走がハイレベル戦」は同走馬のその後の成績を使うため、取込が遅れると付きにくくなる。
- 指数帯別回収率ページの表は固定値。データが増えて見直すときは `ippen_plus_wf.py` → `gen_ippen_table.py` を再実行して差し替える。

## 6. 実装と突き合わせ

- サーバー: `src/server.ts` の `computeIppenSignals()`。`/api/races/:raceKey/entries` の各行に `ippen_n`（個数）・`ippen_items`（内訳）を付ける。
- 出馬表: `public/entries.html`（列#9、`ippenBg()`）。
- 参照計算: `python/research/ippen_signal_ref.py <YYYYMMDD>`（その日の全馬の内訳を JSON で出力）。
- 2026-09-20・2026-06-28 の2開催日626頭で、API と参照計算の内訳が完全一致することを確認済み。
- **要素を見直すときは、server.ts と ippen_signal_ref.py の両方を同じ定義に直し、突き合わせをやり直すこと。**
- 研究用スクリプト（`python/research/`）: `ippen_build.py`・`ippen_build2.py`（データ構築）→ `ippen_plus_screen.py`（候補の下見）→ `ippen_plus_wf.py`（walk-forward）→ `gen_ippen_table.py`（ページ用の表）。
