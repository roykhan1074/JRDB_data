> 最終更新: 2026-09-27
>

## 1. 概要

**穴妙味指数**は、EX指数（コース別, `T_ANABA_SCORE.course_score`）が高いにもかかわらず、生の能力指数であるIDMがJRDBの機械判定で「印」を得るほど突出していない馬（`T_KYI.in_idm IS NULL`）を、基準オッズ15〜30倍という穴馬ゾーンに限定して抽出するグレード。「市場参加者が注目しがちな素のIDMでは目立たないが、コース適性等を加味した複合指数では高評価な馬＝見落とされやすい妙味馬」を捉える設計。

ETL・専用テーブルは持たない。既存の`T_ANABA_SCORE.course_score`・`T_KYI.in_idm`・`T_KYI.kijun_odds`のみから、`entries.html`側で毎回その場で計算する純粋関数（`anabaMyomiGrade()`）。

---

## 2. 対象馬の定義（グレード付与条件）

以下の3条件をすべて満たす馬のみがグレードを持つ。いずれか1つでも外れる場合はグレードなし（無印）。

| 条件 | 内容 |
|---|---|
| ① コース別EX指数 | `T_ANABA_SCORE.course_score >= 50` |
| ② IDM印 | `T_KYI.in_idm IS NULL`（IDM印なし） |
| ③ 基準オッズ | `T_KYI.kijun_odds` が15倍以上30倍以下 |

条件①を満たす範囲でさらに2段階に分ける。

| グレード | course_score範囲 |
|---|---|
| A | `>= 100` |
| B | `50 <= course_score < 100` |

## 3. 指数の仕組み

### 3.1 計算式（`public/entries.html` `anabaMyomiGrade()`）

```js
function anabaMyomiGrade(anaba, idmMark, odds) {
  if (isNaN(anaba) || idmMark !== null) return null;
  if (isNaN(odds) || odds < 15 || odds > 30) return null;
  if (anaba >= 100) return 'A';
  if (anaba >= 50)  return 'B';
  return null;
}
```

引数はすべて`entries.html`が出馬表APIから既に取得済みのフィールド（`anaba_course_score`, `in_idm`, `kijun_odds`）をそのまま渡すのみで、追加のAPI呼び出しやDBテーブルを必要としない。

### 3.2 なぜ`course_score>=25`ではなく`>=50`からグレードを付けるのか（重要な設計判断の経緯）

発見当初は`course_score>=25`（IDM印なし×オッズ15-30倍）の母集団全体で単勝回収率が2020〜2026年の7年連続100%超（103.9〜126.7%）という結果が出ていた。しかし**実装直前にこの母集団をさらに細分化したところ、次のことが判明した**。

| course_score帯 | n（全期間） | 単勝回収率 | 複勝回収率 |
|---|---:|---:|---:|
| 25-50 | 6,929 | 89.3% | 76.1% |
| 50-75 | 4,111 | 112.5% | 89.1% |
| 75-100 | 2,239 | 115.6% | 80.5% |
| 100-150 | 1,948 | 183.1% | 104.2% |
| 150-200 | 649 | 198.9% | 109.5% |
| 200+ | 301 | 237.4% | 123.4% |

`25-50`帯は母集団の43%を占めるにもかかわらず、年別に見ると単勝回収率が59.1%〜123.8%と不安定で、複勝回収率は7年間すべて90%を下回った。「course_score>=25全体で7年連続100%超」という結果は、実質的に**`100+`帯（後述の通り極めて強い）が`25-50`帯の弱さを平均でならして覆い隠していただけ**だったと判明した。これは過去に却下した「情報指数-1」のケースと同型の「一部の強い区分が弱い区分を覆い隠す」パターンである。

このため、`25-50`は非採用とし、実測で明確な優位性が年単位で確認できた`50-100`（B）・`100+`（A）の2グレードのみを採用した。

6/7年で単勝回収率100%超（2024年のみ93.5%）。

### 4.2 グレードA（course_score >= 100）年別

| 年 | n | 勝数 | 単勝回収率 | 複勝回収率 |
|---|---:|---:|---:|---:|
| 2020 | 423 | 18 | 122.2% | 102.3% |

7年連続で単勝回収率100%超（122.2〜254.0%）。複勝回収率も6/7年で100%超（2025年のみ97.2%）。

### 4.3 集中度チェック（グレードA+B合算、course_score>=25の母集団に対して実施）

上位10勝（全605勝中1.7%）を除外しても単勝回収率107.1%を維持。一発の超大穴的中に依存した見せかけの数字ではないことを確認済み。

### 4.4 一般母集団との比較

同一オッズ帯（基準オッズ15-30倍）の一般馬（本指数の条件を満たさない馬）の単勝回収率は75.9%。グレードA・Bはこれを大きく上回っており、市場が既に織り込んでいる水準を超えた真の上乗せ効果であることを確認済み。

## 5. 先読みバイアスについて

> **⛔ 2026-10-04 追記：真のholdout検証で崩壊を確認。** 下記の「7年連続で安定しているから先読みバイアス単体では説明できない」という推論は誤りだった。全期間プール集計では、どの年のスコアにもその年自身の結果が同じように混入するため、先読みがあっても年別成績は揃って良く見える（年別安定性は先読みの反証にならない）。
>
> `sql/anaba_index.sql` Part3を学習期間（〜2023-12-31）の`T_ANABA_RACE_LOG`のみで再集計し、2024〜2026年を採点したholdout検証の結果（新馬・障害除外、単勝回収率）：
>
> | | 2024 | 2025 | 2026 | 3年計 単勝 | 3年計 複勝 |
> |---|---:|---:|---:|---:|---:|
> | 穴妙味A（先読みあり） | 222.7%(n=451) | 203.3%(n=462) | 208.5%(n=317) | 211.8% | 105.4% |
> | 穴妙味A（holdout） | 68.4%(n=567) | 95.3%(n=564) | 84.4%(n=381) | 82.5% | 85.3% |
> | 穴妙味B（先読みあり） | 97.8%(n=914) | 112.7%(n=942) | 110.4%(n=702) | 106.7% | 90.7% |
> | 穴妙味B（holdout） | 50.1%(n=1006) | 88.8%(n=979) | 83.1%(n=789) | 73.1% | 73.2% |
> | 同オッズ帯(15-30倍)の一般母集団 | | | | 77.4%(n=29,942) | |
>
> holdoutでは穴妙味A/Bとも一般母集団並み（A 82.5%、B 73.1%）で、上乗せ効果は確認できない。**本指数の好成績はEX指数(course_score)の全期間集計による先読みバイアスの産物と判断する。**

（以下は2026-09-27時点の記述。上記追記により結論は否定済み）

`course_score`（`T_ANABA_SCORE`）自体は全期間プールでファクター集計する設計のため、EX指数単体としては先読みバイアスのリスクを抱える（CLAUDE.md「指数/スコアETL実装時の必須チェック」4番参照）。ただし本指数のバックテスト（§4）は年別に単勝回収率を集計しており、**2020年から2026年まで7年間連続で結果が安定している**ことを確認済みである点は先読みバイアス単体では説明できない頑健性を示す。とはいえ完全なwalk-forward検証（学習期間のみでファクターを集計し、真のholdout期間で採点する形）は実施していない点は限界として明記する。

`in_idm`・`kijun_odds`はいずれもレース前に公表される値であり、これ自体に先読みの余地はない。

## 6. 実装箇所

### entries.html

- 列#25「穴妙味」（56px、`hdr-nowrap`）。セル背景はA=`#fbcfe8`（ピンク）、B=`#bbf7d0`（薄緑）。文字は既存の`sp-a`/`sp-b`クラス（CLAUDE.mdのA〜Eグレード色規約の正典）をそのまま流用。
- **2026-09-27、列#25は元々「厩指穴信頼」（厩舎指数×穴セグメントの信頼度グレードS〜F）だったが、ホールドアウト検証で失敗が確定していたため、ユーザー指示によりこの列を穴妙味指数の表示に差し替えた。** 列を新規追加せず、失敗済み指数の表示枠を再利用する形。旧「厩指穴信頼」のJS計算（`kytGrade`/`kytTip`）・APIフィールド（`kyusha_anaba_place_rr`等）は`watchlist.html`等が引き続き参照するため削除していない（entries.htmlのこの列での表示のみ差し替え）。
- `evaluateRaceSignals()`の`edge`カテゴリ（推奨買い目パネルのタグ）：グレードA→weight3、B→weight2で「穴妙味指数A/B」タグを表示。タグ色は`CAT_STYLE.edge`（`#fbcfe8`/`#9d174d`）。

### src/server.ts

- `GET /api/races/:raceKey/entries` に `k.in_idm` を追加済み（`anaba_course_score`・`kijun_odds`は既存フィールドを流用）。

新規テーブル・ETL・APIエンドポイントは追加していない。

## 7. 現状のスコープと注意点

- グレードなし（無印）の馬は「妙味がない」ことを意味しない。単に「このセグメント（IDM印なし×オッズ15-30倍×course_score>=50）で検証済みの範囲外」というだけであり、他の条件下での妙味の有無は未検証。
- `course_score`が同一のETL（`sql/anaba_index.sql`）で再計算されるたびに、本指数のグレード判定結果も連動して変わる。`anaba_index.sql`側の設計変更（HAVINGガード・shrinkage等）を行った場合は、本指数のバックテスト（§4）も再検証が必要。
- 完全なwalk-forward検証（真のholdout）は未実施（§5参照）。今後の課題。
